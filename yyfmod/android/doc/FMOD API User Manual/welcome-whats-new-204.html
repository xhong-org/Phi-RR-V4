What's New in 2.04?

This section describes the major features introduced in the 2.04 release. See the Detailed Revision History for information regarding each patch release.

Audio Table Instruments

Playing sounds from audio tables has been simplified with the introduction of the audio table instrument. Playing a sound from an audio table previously required the use of a programmer instrument in conjunction with FMOD_STUDIO_EVENT_CALLBACK_CREATE_PROGRAMMER_SOUND and FMOD_STUDIO_EVENT_CALLBACK_DESTROY_PROGRAMMER_SOUND callbacks. While this workflow is still available, you can now enqueue keys for any Studio::EventInstance containing an audio table instrument using Studio::EventInstance::addAudioTableKey. When an audio table instrument is triggered it pops a key from the queue and plays the corresponding key from the audio table. Once the list is exhausted the instrument no longer triggers.

DSP API Improvements

The DSP API has been simplified to remove the read, and shouldiprocess callbacks, so all plugins must now use FMOD_DSP_PROCESS_CALLBACK to be compatible with FMOD 2.04. FMOD_DSP_PROCESS_CALLBACK has been modified to remove the two FMOD_DSP_PROCESS_OPERATION modes, and is now solely responsible for processing sample data. DSP idle behavior is now controlled by the new FMOD_DSP_SETSILENCE_FUNC and FMOD_DSP_SETBYPASS_FUNC DSP state functions that can be called when the plugin should stop processing. The new FMOD_DSP_DESCRIPTION::defaultcooldown field can also be used to configure the number of samples to wait after receiving no signal before the DSP should automatically go idle.

Full details of the required migration steps can be found in the Migrating from 2.03 to 2.04 section of the DSP Plugin API Guide.

HTML5 Improvements

The HTML5 platform has been upgraded with a modernized JavaScript API, along with support for TypeScript/IntelliSense, Node.js, and NPM package install support. File and bank loading has also been improved with a new "fetch" API and updated file callback support. FMOD for HTML5 has deprecated asm.js support and is now WebAssembly only.

Minimum / Maximum Distance Overrides

A new includeOverrides flag has been added to Studio::EventDescription::getMinMaxDistance. When set to true, the function evaluates the event's FMOD_STUDIO_EVENT_PROPERTY_MINIMUM_DISTANCE and FMOD_STUDIO_EVENT_PROPERTY_MAXIMUM_DISTANCE properties, as well as the overriding min and max distance of all spatializer DSPs (FMOD_DSP_TYPE_PAN and FMOD_DSP_TYPE_OBJECTPAN) on the event's master track, and returns the minimum of all min distances and maximum of all max distances from the respective min and max out parameters.

This means you can now accurately query the min and max distance of a Studio::EventDescription without needing to first play an Studio::EventInstance of that event, allowing for improved distance-based performance optimizations.

Multiband Dynamics Legacy Mode

In 2.03 the multiband dynamics effect used a ratio calculation that produced inaccurate dynamic response results. This caused an audibly reduced amount of attenuation or gain to be applied during playback. This has been corrected in 2.04, and any new multiband dynamics effect instances now use the corrected ratio calculation. To preserve existing behavior, any existing multiband dynamics effect instances are switched over to using the legacy ratio calculation during FMOD Studio project migration.

If you prefer the old ratio calculation, or if you migrate your project and are manually creating FMOD_DSP_MULTIBAND_DYNAMICS instances using the API, you can set the FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE int parameter to FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE_20300 to use the previous calculation.

Per Sound Resampler Configuration

The resampler method (FMOD_DSP_RESAMPLER) can now be configured per-sound using FMOD_CREATESOUNDEXINFO::resamplermethod. This allows anti-aliasing to be applied to individual sounds rather than system-wide with FMOD_ADVANCEDSETTINGS::resamplerMethod.

Studio API Asset Markers

Studio::EventInstances and Studio::EventDescriptions can now have an FMOD_STUDIO_EVENT_CALLBACK_ASSET_MARKER callback registered which is triggered whenever an instrument's playhead passes over an FMOD_SYNCPOINT embedded in any of its assets. This works for asset markers created in FMOD Studio, as well as syncpoints embedded in assets played back via a programmer instrument.

API Differences

APIs that have changed with this release that haven't been called out explicitly above.

Studio API

  • Modified Studio::EventDescription::GetMinMaxDistance to add includeOverrides
  • Added FMOD_STUDIO_EVENT_CALLBACK_ASSET_MARKER
  • Added FMOD_STUDIO_ASSET_MARKER_PROPERTIES
  • Added Studio::hashAudioTableKey
  • Added Studio::EventInstance::addAudioTableKey
  • Added Studio::EventInstance::clearAudioTableKeys
  • Added FMOD_STUDIO_SYSTEM_CALLBACK_GET_SOUND_INFO
  • Added FMOD_STUDIO_PARAMETER_AUTOMATIC_AUDIO_TABLE_KEY_COUNT
  • Modified FMOD_STUDIO_SOUND_INFO to add keyhash

Core API

  • Renamed DSP::setChannelFormat to DSP::setInputChannelFormat
  • Renamed DSP::getChannelFormat to DSP::getInputChannelFormat
  • Modified DSP::setInputChannelFormat to remove channelmask
  • Modified DSP::getInputChannelFormat to remove channelmask
  • Modified DSP::getOutputChannelFormat to remove inmask, outmask
  • Removed FMOD_DSP_ShowConfigDialog
  • Modified DSP::getInfo to remove configwidth, configheight, and to add mode
  • Removed FMOD_INIT_MIX_FROM_UPDATE
  • Removed FMOD_SOUND_TYPE_MEDIA_FOUNDATION
  • Modified FMOD_CREATESOUNDEXINFO to add resamplermethod

DSP Plugin API

  • Renamed FMOD_DSP_BUFFER_ARRAY to FMOD_DSP_BUFFER
  • Modified FMOD_DSP_BUFFER to remove numbuffers, bufferchannelmask, and return a single pointer for buffer
  • Added FMOD_DSP_COOLDOWN_INFINITE
  • Added FMOD_DSP_MODE with FILTER and GENERATOR values
  • Removed FMOD_DSP_PROCESS_OPERATION
  • Removed FMOD_DSP_READ_CALLBACK
  • Removed FMOD_DSP_SHOULDIPROCESS_CALLBACK
  • Added FMOD_DSP_GETIDLETIME_FUNC
  • Added FMOD_DSP_SETCOOLDOWN_FUNC
  • Added FMOD_DSP_SETBYPASS_FUNC
  • Added FMOD_DSP_SETSILENCE_FUNC
  • Added FMOD_DSP_SETOUTPUTFORMAT_FUNC
  • Modified FMOD_DSP_DESCRIPTION to remove numinputbuffers, numoutputbuffers, read, shouldishouldiprocess, and to add mode, defauldefaultcooldown, inchannels, outchannels
  • Modified FMOD_DSP_STATE_FUNCTIONS to remove getidletime, setcooldown, setbypass, setsilence, setoutputformat
  • Deprecated FMOD_DSP_STATE::channelmask
  • Deprecated FMOD_DSP_STATE::source_speakermode
  • FMOD_PLUGIN_SDK_VERSION has changed from 110 to 204

DSP Effects

  • Added FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE
  • Added FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE_TYPE with FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE_LATEST and FMOD_DSP_MULTIBAND_DYNAMICS_LEGACY_MODE_20300 values
  • Added FMOD_HAPTICS_INTENSITY
  • Added FMOD_HAPTICS_PLAY_COUNT
