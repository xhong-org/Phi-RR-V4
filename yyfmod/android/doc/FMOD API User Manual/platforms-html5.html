HTML5 Specific Starter Guide

Use this guid for information on what libraries to import or link, usage guides with code examples and help with web environment limitations.

Compatibility

  • FMOD was tested to support the following browser versions and above: Firefox 79, Safari 14.1.0, Chrome 85.
  • FMOD is compiled using Emscripten 4.0.8.
  • FMOD requires a browser to support Web Audio using FMOD Browser based libraries.
  • FMOD requires a user interaction (a click / touch, or key press) to initiate audio using FMOD Browser based libraries. This is a security measure to avoid unwanted audio.
  • FMOD requires WASM support when using Javascript/TypeScript. Legacy ASM.JS libraries are available in FMOD 2.02.
  • FMOD requires browser support for FMOD_OUTPUTTYPE_AUDIOWORKLET and FMOD_OUTPUTTYPE_AUDIOWORKLETP output modes, otherwise the legacy FMOD_OUTPUTTYPE_WEBAUDIO is used.
  • For 5.1 / surround sound support, modern browers are required, such as Mozilla Firefox verified in version 50.1.0 or Chrome version 80 and above.
  • Browsers that support SharedArrayBuffer will get access to pthread support, but user has to use the 'P' versions of the FMOD libraries. See compatibility details here.
  • FMOD supports Node, though is only support for FMOD_OUTPUTTYPE_NOSOUND due to lack of a browser Audio Context. Use it for testing or server based 'headless' processing.

Installing with NPM

npm install fmod-2.4.00.tgz

Note that this installs all varieties of FMOD, you may want to trim out the libraries you dont want (see Libraries).

The package will be installed as 'fmod', you can then use that to import the library you want to use
i.e.

import createFMOD from 'fmod/fmod';     // Core API Browser library

import createFMOD from 'fmod/fmodPL';   // Core API pthreads with logging

import createFMOD from 'fmod/fmodstudio';     // Studio API release

import createFMOD from 'fmod/fmodstudioN';     // Studio API Node library

See Libraries for more on library varieties.

Javascript JSDoc import of TypeScript definitions:

/**
 * Core API
 * @typedef {import('fmod/fmod').FMOD} FMODType
 * etc..
 */

Typescript:

import FMOD from "fmod/fmod";  // Core API

See Using FMOD with JavaScript / TypeScript for more on using TypeScript definitions.

Libraries

FMOD provides different binaries covering different runtime formats and compatibility.
First choose your runtime environment.

  • Browser - Default for Browser based audio.
  • Node - Default for servers (no audio output, processing only).

fmod_reduced Core API is available, with some lesser used features removed to save space. Studio API libraries include this by default, so use the logging 'L' versions to access all features if requried.

Browser

FMOD provides different binaries covering the use single-threaded mode vs 'pthread' support.
Choose your threading environment.

  • Single Threaded - All mixing / streaming performed on main thread. Callback friendly.
  • pthreads - Requires SharedArrayBuffer and CORS / HTTPS support. Audio does not stutter when main thread stalls. Not callback friendly.

FMOD browser libraries are exported as ECMAScript Module (ESM). Use 'import' and follow this guide for usage.

Using FMOD with JavaScript / TypeScript

TypeScript / JSDoc support

Import fmod.d.ts or fmodstudio.d.ts to support typechecking and autocomplete / annotations for FMOD functions and constants.
JSDoc is supported for .JS files.

With TypeScript it is a simple matter of autocompleting the type definitions from FMOD, i.e:

import FMOD from "./fmod";  // uses fmod.d.ts

let system:FMOD.System;

With Javascript there is some defining required to get some simple type definitions to use with JSDoc first.

import FMOD from "./fmod";  // uses fmod.d.ts

/**
 * @typedef {import('./fmod').FMOD.Channel} Channel
 * @typedef {import('./fmod').FMOD.ChannelControl} ChannelControl
 * @typedef {import('./fmod').FMOD.ChannelGroup} ChannelGroup
 * @typedef {import('./fmod').FMOD.DSP} DSP
 * @typedef {import('./fmod').FMOD.DSPConnection} DSPConnection
 * @typedef {import('./fmod').FMOD.Geometry} Geometry
 * @typedef {import('./fmod').FMOD.Reverb3D} Reverb3D 
 * @typedef {import('./fmod').FMOD.Sound} Sound 
 * @typedef {import('./fmod').FMOD.SoundGroup} SoundGroup
 * @typedef {import('./fmod').FMOD.System} System
 * @typedef {import('./fmod').InitOptions} InitOptions
 * @typedef {import('./fmod').FMOD.CREATESOUNDEXINFO} CREATESOUNDEXINFO
 * @typedef {import('./fmod').FMOD} FMODType
 *
 * Add more here if needed.
 */

/** @type {System} */
let system;

Application setup

To set up a JavaScript application import the createFMOD() factory function from the relevant FMOD library (pthread support, logging etc), with some pre-initialize options. The createFMOD function always returns a Promise.

TypeScript Example:

import createFMOD from './fmod.js'
import { FMOD, InitOptions } from "./fmod";

let gFMOD: FMOD;

async function main()
{
    const opts:InitOptions = {
        INITIAL_MEMORY: 64 * 1024 * 1024,   // Optional. FMOD Heap defaults to 16mb which is enough for this demo, but set it differently here for demonstration (64mb)
        window: window,                     // Optional. Specify main window handle from a different context if needed.
    }

    // Create the FMOD object with options.
    gFMOD = await createFMOD(opts);

    try
    {
        // Create the FMOD System object.
        let system = gFMOD.System_Create();

        // Initialize FMOD
        system.init(1024, gFMOD.INIT_NORMAL);   // 1024 virtual channels
    }
    catch (e)
    {
        console.log("ERROR: ", e);
    }

    // Rest of app...
}

main();

Supplying your own window handle and memory limit

Passing an option object (optional) to createFMOD gives the following options:

  • INITIAL_MEMORY option: FMOD defaults to 16mb of memory to load sounds with and create FMOD objects with. Use the following global before calling the main FMOD constructor object, to control how much memory to use. FMOD uses ALLOW_MEMORY_GROWTH, which will allow memory to grow dynamically from INITIAL_MEMORY up to a maximum of 2GB.
  • window: Before any FMOD API calls, pass a different to window handle to FMOD here, this is where the audio context will be created from.

Loading files into FMOD

FMOD lets you load data from the host in a few different ways, depending on your setup.

Via memory

The simplest way to avoid issues with threads and callbacks, is if you have raw buffer data in memory that you can to pass to FMOD.
This method requires memory to be preallocated for the buffer, which FMOD then duplicates when loading, so there will be double memory usage temporarily until your original buffer is freed.

The load_from_memory has an example of this

var chars  = new Uint8Array(e.target.result);
var result;
var exinfo = {}
exinfo.length = chars.length;

var sound = gSystem.createSound(chars.buffer, FMOD.LOOP_OFF | FMOD.OPENMEMORY, exinfo);

FMOD_OPENMEMORY_POINT Cannot be supported as the garbage collector moves memory around after System::createSound is called, making the data invalid.

Via callbacks

Note! File callbacks will not work with pthreads if they are called from a thread. Use FMOD_STUDIO_INIT_LOAD_FROM_UPDATE and FMOD_STUDIO_INIT_SYNCHRONOUS_UPDATE to force it into the main thread if using Studio API.

If you have a file system you can use file callbacks to load data into FMOD. See System::setFileSystem, or Studio::System::loadBankCustom
In load_bank example, there is a demonstration of this

var info = {}

info.opencallback = customFileOpen;
info.closecallback = customFileClose;
info.readcallback = customFileRead;
info.seekcallback = customFileSeek;
info.userdata = filename;

var sound = await gSystem.loadBankCustom(info, FMOD.STUDIO_LOAD_BANK_NORMAL);

In this case the filename is passed as userdata to let the callback get information for what file to load.
Here is the customFileOpen callback getting the filename and opening a file handle.
The file is opened in this case with a special FMOD provided file API. Replace this with your own API.

function customFileOpen(name, filesize, handle, userdata)
{
    // We pass the filename into our callbacks via userdata in the custom info struct
    var filename = userdata;

    return FMOD.file_open(gSystemLowLevel, filename)
}

To read data in the callback, into the buffer that FMOD has provided, FMOD has used a special technique where it passes the internal WASM memory address, instead of a normal JavaScript buffer.
This means to write data to FMOD's buffer you must use FMOD.setValue / FMOD.copyToPtr functions using the FMOD buffer address.

function customFileRead(handle, buffer_out, sizebytes, bytesread, userdata)
{
    // Read from the file into a new buffer. This part can be swapped for your own file system.
    var buffer = getData(handle)   // User read function that returns a javascript buffer

    // Copy the new buffer contents into the buffer that is passed into the callback. 'buffer' is a memory address, so we can only write to it with FMOD.setValue
    FMOD.copyToPtr(buffer_out, buffer, buffer.byteLength);
}

Helper functions

FMOD comes with some functions to aid with writing/reading data to and from FMOD internal memory.

  • FMOD.setValue. To write a single value to a buffer returned by FMOD from JS.
  • FMOD.getValue. To read a single vlaue from a buffer returned by FMOD into JS.
  • FMOD.copyToPtr. To write data to a buffer returned by FMOD from JS.

Suspending audio on browser focus change

It is possible to suspend the audio at the browser level when the user switches focus from a web browser tab, or minimizing the browser.
Use System::mixerSuspend and System::mixerResume from a focus change event like 'visibilitychange'.

TypeScript Example:

// Optional. Mute audio on tab change or minimize/maximize.
document.addEventListener("visibilitychange", () => {
    if (document.hidden)
    {
        gSystem.mixerSuspend();
    }
    else
    {
        gSystem.mixerResume();
    }
});

Using FMOD with C/C++

If you have a C/C++ program that uses FMOD and are converting it to JavaScript using Emscripten, you will need to link the relevant FMOD binaries as per the Emscripten Documentation, and ensure the following flags are added in your Emscripten compilation arguments:

-s WASM=1 -s ALLOW_MEMORY_GROWTH=1 -s EXPORTED_RUNTIME_METHODS=ccall,cwrap,setValue,getValue -s ASYNCIFY

Flags for pthread build

Add these flags on top of the standard flags above:

For Core API

-pthread -s PTHREAD_POOL_SIZE=6 -s AUDIO_WORKLET -s WASM_WORKERS

Core API has potentially 6 threads. Mixer thread, stream thread, FMOD_NONBLOCKING thread, file thread and 2 convolution reverb threads.

For Studio API

-pthread -s PTHREAD_POOL_SIZE=9 -s AUDIO_WORKLET -s WASM_WORKERS

Studio API has potentially 9 threads. Core API mixer thread, stream thread, FMOD_NONBLOCKING thread, file thread, 2 convolution reverb threads and Studio API update thread, sample load thread and bank load thread.

Performance tuning

CPU Overhead

By default FMOD mixes at 48000hz. If the browser is not running at that rate, it will introduce a resampler to convert the rate, which consumes CPU time and adds a DSP block worth of latency.
This can be solved by querying the hardware's rate before System::init, and calling System::setSoftwareFormat to the same rate as the output. Here is an example (from the PlaySound example):

var info = gSystem.getDriverInfo(0);
gSystem.setSoftwareFormat(info.systemrate, FMOD.SPEAKERMODE_DEFAULT, 0)

Audio Stability (Stuttering)

Some devices cannot handle the default buffer size of 4 blocks of 1024 samples (4096 samples) without stuttering, so to avoid this set the buffer size in your application to 2 blocks of 2048.
Here is an example

gSystem.setDSPBufferSize(2048, 2);

Make sure System::update is being called frequently enough for mixing / streaming to be processed from the main thread.

If FMOD_OUTPUTTYPE_AUDIOWORKLET is used the mixer runs in the main thread but feeds pcm data to the asyncrhonous FMOD_OUTPUTTYPE_AUDIOWORKLET worklet. Use pthreads and FMOD_OUTPUTTYPE_AUDIOWORKLETP (default in pthreads libs) for true background mixing.

In pthread mode the stream thread will process data in the background but threaded streams will not support JavaScript callbacks (pthreads cannot access main thread JavaScript objects). Use FMOD_INIT_STREAM_FROM_UPDATE to make callbacks work again.

Reduced Feature build

The Core API libraries provide _reduced library file variations which can be used optionally.
The _reduced library is a smaller subset of features. This provides a smaller file size footprint for distribution purposes.

fmodstudio.js/fmodstudio.a/fmodstudio.wasm and their 'P' (SharedArrayBuffer/pthread) versions include the reduced library by default. To get the full feature set use the logging version of each file instead. This enables logging but you can turn it off with Debug_Initialize.

Codec Support

The following file formats are removed in favour of the .FSB file format only. .FSB support includes vorbis, FADPCM and pcm audio formats:

  • AIFF file format support
  • DLS file format support
  • FLAC file format support
  • WAV file format support
  • MOD file format support
  • S3M file format support
  • XM file format support
  • IT file format support
  • MID/MIDI file format support
  • MP2/MP3 file format support
  • OGG file format support
  • PLS/M3U file format support

Threads and limitations in HTML5

FMOD supports pthreads with the 'P' varieties of the libraries (fmodP.js/fmodstudioP.js and variants.)
For legacy support, pthread libraries should not be used, and special required care to avoid skipping/stuttering audio.

Legacy support

The single threaded build does not support any threaded background processing, so the developer must call System::update regularly to keep the audio running without interruptions.

pthread support

The 'P' versions of the FMOD libraries support threaded mixing, streaming and FMOD_NONBLOCKING support.

An important limitation to note is that user callbacks will not fire from a pthread, as JavaScript objects cannot be shared between threads.

DSP Effect support

The following effects / mixer code is removed:

  • Envelope follower DSP support
  • Cubic / Spline and 'none' interpolation support. Linear interpolation only.

Known Issues

The following items are not supported:

  • Networking. A disadvantage of the web platform is the lack of networking sockets. There are alternatives provided by our toolchain, however they require additional servers running as a proxy. This limitation means we cannot implement Live Update and Profiling features between the running code and FMOD Studio. Additionally this means we cannot support internet streaming of audio (netstreams).
  • All Geometry based functionality.
  • System::loadPlugin
  • Studio::EventDescription::setCallback. Use Studio::EventInstance::setCallback as a workaround for now.
  • Callbacks from threads (user-created streams, timeline based callbacks in studio api etc). Due to JavaScript objects not being able to be shared across threads. See pthread section on compatibility and workarounds for solutions.

The following callbacks remain unimplemented at this point, so they will not work:

  • FMOD_3D_ROLLOFF_CALLBACK
  • FMOD_DSP_CALLBACK
  • FMOD_FILE_ASYNCREAD_CALLBACK
  • FMOD_FILE_ASYNCCANCEL_CALLBACK
  • FMOD_SOUND_NONBLOCK_CALLBACK
  • FMOD_SYSTEM_CALLBACK
  • FMOD_STUDIO_COMMANDREPLAY_FRAME_CALLBACK
  • FMOD_STUDIO_COMMANDREPLAY_LOAD_BANK_CALLBACK
  • FMOD_STUDIO_COMMANDREPLAY_CREATE_INSTANCE_CALLBACK
